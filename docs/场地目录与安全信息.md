# 资源目录与安全信息

## 资源层级与演示数据

`Lab`表示资源管理单元，不必然等同一间物理实验室；一个管理单元可关联多项`Resource`。`Resource.kind=ROOM`代表可单独预约的场地，`RoomDetail`保存位置、容量、类别和设施；`Resource.kind=EQUIPMENT`代表可单独预约的设备，固定设备可与场地建立约束关系。管理单元、场地和设备的实际组织关系应由授权岗位核验。

课程演示种子数据包含3个管理单元、6间场地和9项设备，每个管理单元各有2间场地。名称、建筑位置、容量、用途、设施和状态均为模拟数据，不代表任何高校真实资产数量、房间分布或运行制度。固定机器人平台用于演示设备与场地的关联限制，ROOM-302用于演示维护状态。新装种子命令仅补齐演示主数据，不覆盖已有业务记录。

管理单元启用状态、资源服务状态、设备实物状态和目标时段可用性分别表达。管理单元停用时，其下资源不得新预约；这不会伪造既有预约取消、设备归还或场地离场事实。正式导入前需由责任岗位核对组织、建筑、楼层、房间、容量、设备位置、固定关联、角色范围及有效状态。

## 开放日历与真实图片边界

目前一个管理单元或场地在某星期几、某有效版本内只支持一段连续开放时间；单日例外支持一段时间或全天关闭，不能表达上午、下午分开的多个窗口。这是当前实现限制，不是已确认的学校制度。是否需要多时段需依据目标组织正式开放日历判断。

网站和小程序没有目标学校授权的实拍图片，因此使用明确的无照片占位，不借用其他高校实验室图片冒充本校场地。课程模拟目录也不构成照片实体、上传流程或储存服务。后续只有取得场地责任方确认及网站、小程序和公开仓库所需的展示与再分发授权后，才能将具体图片关联到相应资源。

## 安全信息的作用范围

系统支持两种彼此独立的安全信息范围：

1. **管理单元通用信息**：关联一个`Lab`管理单元，适用于当下归属该单元的各场地和设备。
2. **资源专属信息**：关联一个具体`Resource`，仅适用于该资源，可对应场地或设备。

一个资源可以同时显示所属管理单元通用信息和自身专属信息。系统不预设二者之间的优先级，也不把房间专属信息自动继承到与房间关联的固定设备；责任岗位应依据正式批准文件明确适用范围。设备和场地范围、信息版本及确认记录分别可追溯。数据库要求每个安全信息版本恰好关联一个管理单元或一个资源，避免模糊的多态引用。

## 版本、复核与阅读确认

1. 具有对应管理单元授权的实验室管理员选择管理单元通用范围或某一具体资源，依据责任岗位提供的正式材料编制安全信息草稿，登记来源、版本、生效日期、复核期限、适用对象和编制原因。
2. 草稿提交复核后仅在授权管理页面可见。范围内另一名实验室管理员复核并记录意见；提交者不能复核发布本人版本。系统管理员、实验教学中心主任或维修人员不会因其他身份自动取得该项审批权。
3. 发布时保留原版本、审核责任、来源及审计事实。发布新版本不取消预约、不伪造用户已阅读。只有责任岗位明确开启“要求阅读确认”的当前有效版本才触发确认校验；未发布、过期、待复核的信息不会被标为现行有效内容。
4. 需要确认时，学生或教师对具体的当前发布版本进行确认。系统可在创建预约、批准申请及办理实际使用前检查适用版本的确认记录。确认绑定用户和版本，只表明系统记录了阅读确认，不证明完成培训、考核、门禁授权、准入或现场检查。
5. 发布需确认的新版本后，系统通知受影响范围内未来已确认预约的申请人，并列出其关联预约编号；管理单元范围通知该管理单元下的预约，资源专属范围只通知对应资源预约。原预约保持原状态，实际使用前重新核对适用版本。外部消息失败不回滚已经发布的版本。
6. 页面可保留已发布历史供追溯；超过复核期限的版本显示“过期或待复核”，不得冒充当前已核实制度。

上述流程是课程演示系统的可配置设计。当前没有来自目标学校的批准安全文本，演示种子不会生成风险类别、防护用品、操作步骤、禁令或应急联系人；没有已发布信息时不自动阻断预约。这不是对真实现场安全状态的判定。哪些岗位有权编制、谁负责独立复核、哪些设备需要强制确认、更新时怎样影响既有预约，均须学校安全责任部门确认后配置。

网站和原生微信小程序读取同一套发布版本并使用服务端领域规则。小程序只显示公开发布字段和当前用户的确认状态；客户端控件不能替代服务端的范围授权或版本校验。
