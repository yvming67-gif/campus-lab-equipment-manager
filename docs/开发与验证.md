# 开发与验证

本页供维护本地独立模拟副本使用。安装与首次运行见[运行指南](运行指南.md)。共享云端演示、机构生产配置和本机私有数据库分别维护，不对共享云端执行模拟数据准备命令。

## 本地开发

```powershell
python tools/start_local.py --setup
```

启动器创建私有虚拟环境、数据库与模拟主数据。默认网页地址为http://127.0.0.1:8000，端口冲突时以窗口为准。网页与后台同时运行，后台每30秒扫描；具备本机runtime配置时尝试每23小时备份，失败一小时后重试。退出与数据库停止方式见运行指南。

## 使用已有PostgreSQL

Windows已有数据库或其他平台需安装requirements.txt中的依赖，并在私有进程环境配置PGHOST、PGPORT、PGDATABASE、PGUSER、PGPASSWORD。已初始化目录优先使用.local/database.json；明确改用外部实例时设置CAMPUS_USE_EXTERNAL_DATABASE=1。不要将密码提交仓库。

初始化身份需具备迁移和安装btree_gist扩展的相应权限；测试身份需能创建独立测试库。不要将这些权限直接等同于机构生产应用身份。完成依赖和配置后，在自己的独立模拟库运行：

```powershell
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

另开同样配置的终端运行python manage.py run_jobs --loop。seed_demo只补齐模拟主数据，不清空已有业务；prepare_demo仅在自己的模拟副本于开放时段准备现场交接样本，不修改电脑时间，不是实际历史业务。不要用SQLite替代本项目的PostgreSQL并发约束验证。

## 验证命令

本机启动器安装完成后，使用虚拟环境解释器；手动创建环境的维护者改为自己的解释器。以下业务测试会创建独立测试库，不清空演示库；不要把测试数据库指向正在使用的生产实例。

```powershell
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py test core.tests core.miniapi_tests core.remediation_tests core.operations_tests core.independent_tests core.logic_alignment_tests core.report_tests core.followup_tests core.backup_tests core.product_tests core.audit_fix_tests --noinput
.venv/Scripts/python.exe tools/test_startup.py
.venv/Scripts/python.exe tools/validate_registry.py
.venv/Scripts/python.exe tools/validate_analysis_models.py
```

联合归档的3项原生恢复集成需显式设置CAMPUS_TEST_PG_BIN为匹配的PostgreSQL客户端bin目录；未配置时明确跳过，不能算恢复通过。详见[联合归档说明](云端备份与恢复.md)。云端配置测试使用独立TLS数据库和模拟存储配置，命令及环境与常规业务测试不同，见[云配置验证记录](云端验证记录.md)。

维护小程序时需要Node.js；常规网页运行不需要。客户端与编译命令见[miniprogram/README](../miniprogram/README.md)。本次审查的额外反例与证据见[全面审查](全面审查/README.md)。

## 可选负载测试和模型导出

```powershell
.venv/Scripts/python.exe manage.py test core.benchmark_tests --noinput
.venv/Scripts/python.exe tools/export_model.py
```

负载测试在独立测试库构造1万台新增设备和10万条历史记录，包含50个会话、每秒10请求的指定负载；有额外运行耗时。历史结果只适用于记录中的样本、查询和网络条件，不承诺所有页面性能。模型导出会更新源文件，应检查差异、对应图源及说明，不能在未核对的情况下覆盖提交。

## 备份与恢复

本机文件存储使用tools/backup_restore.py，可显式加--restore-test恢复到独立命名演练库；已有归档的离线目标恢复使用tools/restore_archive.py。两个工具都不以演练覆盖现有源库，但需要核对实际配置与目标目录。演练库保留，不能按模糊名称批量清除。

云端私有对象使用[tools/backup_cloud.py与联合恢复步骤](云端备份与恢复.md)，不用本机MEDIA_ROOT假设。归档、连接配置、会话与私有证据不得上传公开仓库。本地恢复通过不代表真实Neon/S3恢复已完成。
