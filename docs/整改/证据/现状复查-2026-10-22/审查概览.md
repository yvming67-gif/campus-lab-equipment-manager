# 当前系统完善程度评估

日期：2026年10月22日。基线：01211f98995591719b99b2b66925c62dddf06e2b，开始及结束时业务仓库均无未提交修改。本轮只审查、验证并编写独立评估材料，没有修改业务代码、正式台账、需求或线上配置，没有推送GitHub或触发部署。

## 总体判断

目前可以继续作为共享模拟数据的课程演示系统，但仍存在可复现的报表计算缺陷及界面一致性问题，不能以此前功能检查通过推导所有场景均正确。真实校园应用还缺少学校制度确认、真实身份与消息渠道、云端联合备份恢复和微信容器验收。

值得保留的是设备与场地分别建模、确认与实际使用分开、资格和权限检查、领域事务共用、幂等请求、受限设备复核、异常核实与维修独立验收、受控附件访问及保留审计事实。上述能力的运行证据主要来自既有验收；本轮没有重复运行整个业务套件。

## 本轮实际发现

新增6项：已确认缺陷3项、优化建议2项、应用适配缺口1项；程度为一般1项、轻微5项。原正式台账74项中仍有10项未关闭；本轮关注的未完成记录合计16项，新增记录尚未合并正式台账。

1. AUD-0078：报表没有纳入单日开放例外。独立PostgreSQL实测：全天闭馆应0小时、实际12小时；缩短开放应2小时、实际12小时；额外开放应3小时、实际0小时。预约查询执行了例外，报表却使用周日历，构成真实的规则不一致。优先处理。
2. AUD-0075：资源配置和用户授权缺少搜索及分页。资源管理员页面已观察，系统管理员用户表仅代码核对；不将未来规模风险当作当前已发生超时。
3. AUD-0076：31条本地模拟确认占用，网页只列15条、小程序接口只列30条，没有列表完整性提示。建议说明预览范围并提供按日查询；不能由此推断冲突约束失效。
4. AUD-0077：预约和维修时间线直接展示内部事件/状态代码；实际维修模板片段已用模拟数据渲染确认。
5. AUD-0079：8种现有通知类型回退成“业务进度”，完整调用位置已记录；通知正文仍保留。
6. AUD-0080：正式EXTERNAL渠道也被模板写成“模拟外部”。当前云端使用演示模式，不是当前模拟投递失败，应在正式渠道接入前修正。

## 既有缺口及适用边界

- AUD-0030：当前云端数据库与私有附件的联合备份、异地恢复尚无完成证据；现有本地恢复工具和存储持久化不能替代它。
- AUD-0037：小程序接口和基础模板编译已有记录，但开发者工具容器、真机、合法域名、AppID及正式发布仍待验收。
- AUD-0026、AUD-0040：真实学校SSO和外部消息提供方没有实际联调；模拟成功不能冒充真实认证或送达。
- AUD-0002、0005、0022、0033、0038：风险升级复核、安全报告分级、固定设备区域、信息保留及教学/长期实验制度仍需目标学校确认。课程默认实现不因此变成缺陷，也不等于已经适合任意学校。
- AUD-0027：共享演示HTTPS已经部署并通过此前基础检查，原“外部环境”记录不能笼统理解成未上线。免费实例持续运行、休眠和后台任务时效、真实校园生产配置仍应分别验收。
- 当前选择免费额度耗尽后接受暂停；首次访问此前实际曾等待约42秒。该选择适合低成本演示，不能同时承诺全天候服务或所有提醒按时执行。本轮没有为检验休眠额外做保活或云端压力测试。
