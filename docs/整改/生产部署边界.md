# 生产部署边界

仍以单机Django/PostgreSQL架构为主，未引入消息集群。当前是可运行课程演示与试点准备代码，真实学校SSO、消息渠道、微信正式发布、机构生产环境HTTPS与制度未验收，不宣称正式上线。Render共享演示已有HTTPS、就绪和静态发布证据，其独立配置config.cloud_settings不等同于下述机构生产配置config.production；阶段及当前边界见[交付状态](../交付收尾/当前交付状态.md)。

config.production强制DEBUG=False、DEMO_MODE=False、明确外部数据库、随机独立DJANGO_SECRET_KEY、ALLOWED_HOSTS、身份适配器路径，安全会话/CSRF Cookie与HTTPS重定向。正式环境使用requirements-production.txt安装Waitress，tools/serve_production.py仅绑定127.0.0.1:8080；校验运行身份非超级用户/建库者/建角色者，且不拥有public业务表。不要用Django runserver对外服务。

反向代理负责HTTPS、证书、访问限制和静态文件：先DJANGO_SETTINGS_MODULE=config.production执行collectstatic --noinput，把STATIC_ROOT只读映射至/static/；/media/禁止公共直出，证据仍走鉴权下载。仅信任本机/指定代理传入的HTTPS头，确认代理覆盖而非透传伪造头后才设置CAMPUS_TRUST_HTTPS_PROXY=1。提供ALLOWED_HOSTS实际域名与CSRF_TRUSTED_ORIGINS学校HTTPS来源；开发者工具联调地址不能当正式域名。配置检查之后仍需部署现场验证TLS、Cookie、CSRF、静态、上传、转发、任务托管及故障告警。

DBA创建扩展、表与迁移。应用角色使用tools/provision_app_role.py显式新建，不重置已有角色或密码，最少DML与序列权限，审计仅INSERT/SELECT；在隔离恢复库实测拒绝审计UPDATE/TRUNCATE、禁用触发器和建表。DBA仍能改变保护机制，须受组织职责和独立备份监督。升级后用迁移身份重新核对新增表权限，应用不执行迁移。备份另配只用于备份的身份，具备读取所有需备份表/序列的权限；本地tools/backup_restore.py还需要LOCK TABLE core_evidence IN SHARE MODE所需权限（PG要求该表UPDATE/DELETE/TRUNCATE之一，建议仅UPDATE），不授予表所有权或审计修改权；恢复/创建演练库另使用受控恢复身份。正式worker通过CAMPUS_BACKUP_USER/CAMPUS_BACKUP_PASSWORD显式传备份子进程，缺失不静默使用应用身份。

身份适配器契约：begin(request,state,callback_uri)返回受控HTTPS认证地址；complete(request,expected_state,callback_uri)校验学校签名、颁发者、受众、有效期、单次code及state后返回{school_no,state}。系统只映射既有有效本地用户，不从未校验断言授予管理角色。尚无机构适配实现，测试中的TestIdentity不能用于正式部署。退出/撤权同步及会话寿命应在联调中确认。

微信正式身份另需CAMPUS_MINI_IDENTITY_ADAPTER(code=一次性code)，演示账号密码入口在正式模式拒绝；当前原生客户端仍按演示UI设计，正式wx.login及学校绑定未完成。消息CAMPUS_MESSAGE_ADAPTER接收稳定idempotency_key、内部recipient_id与content；必须有超时、测试白名单、接收者映射和去重契约，返回accepted及receipt_id；只保存回执摘要。缺配置失败重试，绝不生成MOCK成功。供应商接受不等于最终送达或阅读。

运行健康、备份新鲜度、独立副本和容量应由平台监控，服务管理器负责开机启动和退出重启；本地启动器不是跨主机运维平台。完整试点前应完成实际HTTPS环境和连续后台故障演练，才能关闭相关外部验证项。
