# 运行与恢复指南

课程Windows：安装Python3.13 x64后下载仓库，双击根目录“启动演示.cmd”。保留启动窗口；程序创建独立.venv和.local，不删除重复启动时已有记录。数据库和网页端口会避开占用，最终地址以启动窗口为准。已有运行环境也可执行python tools/start_local.py --setup --no-browser。演示账号和密码见根README；不要把演示身份用于校园生产。

后台：启动器同时运行网页和run_jobs --loop，网页就绪不证明任务或备份健康。子进程退出按2/4/8秒最多重启3次，超过次数明确退出，不无限循环掩盖故障。任务循环遇扫描失败记录错误并30秒再试；持久化心跳记录成功/错误。系统管理员访问/operations/health/查看90秒任务新鲜度、24小时备份新鲜度、失败/超期待发数量及副本字段；页面不向普通用户公开。失败投递保留人工联系追加记录。正式系统由平台服务管理器托管网页、任务和外部健康探测，健康异常需实际值守者处理。

日志：.local/application.log按5MiB保留5份，包含请求编号、方法、无查询参数的路径、状态码和耗时；不记录请求正文、认证头或密码。web/jobs日志在启动前轮换，backup-job日志每次备份前轮换。仅维护人员可读，本机访问日志不是防篡改审计；审计事实在受保护数据库。部署代理还须独立轮换访问日志，日志期限待学校确认。

备份：使用安装依赖的Python执行tools/backup_restore.py；可加--replica指定独立目录。完整归档包含数据库、附件与摘要，排除django_session数据。--restore-test为在线隔离演练，需要源连接且不覆盖源库；已有归档的恢复使用下面独立命令，不重新生成源备份：

```powershell
.venv/Scripts/python.exe tools/restore_archive.py --archive "指定备份.zip" --pg-bin "PostgreSQL/bin" --target-db campus_restore_new --media-dir "新的空媒体目录" --host 127.0.0.1 --port 55440 --user campus_restore
```

密码通过进程环境PGPASSWORD由维护者提供，不写入命令、文档或仓库。目标须不存在；媒体目录须不存在或为空。工具不导入Django、不连接源库，验证摘要与路径后恢复，遇错误保留目标供排查，不自动删除或覆盖。恢复后核对关键表计数、未结交接、审核、工单、审计保护和附件摘要；验证会话为0，然后使用新连接启动受控验收，再决定切换。当前本地证据为“源连接配置无效，同实例新目标恢复”，不是源实例已停止或异地灾难演练。

保留默认预览：python tools/backup_retention.py --folder "备份目录" --days 30 --keep 7。确需执行加--apply --replica "独立目录"，先校验副本，拒绝覆盖不同副本。只清理指定目录下过期且超过最少份数的backup-*.zip，不删除数据库。30天/7份为课程可调方案，非学校法定期限。演练数据库不自动清理，维护者核对记录、库名及活动连接后单独批准处理。系统管理员健康端点还返回归档容量与剩余空间，默认归档上限10GiB/剩余至少1GiB，可用CAMPUS_BACKUP_CAPACITY_BYTES及CAMPUS_BACKUP_MIN_FREE_BYTES调整，阈值为课程运行方案。容量和独立副本的磁盘/异地属性需平台监控，目录不同不代表物理故障域不同。

正式配置另见生产部署边界.md；迁移/备份/应用身份不得混用。恢复点初步目标24小时，恢复时长初步目标4小时；本机小样本恢复通过不能证明实际规模下RTO。
