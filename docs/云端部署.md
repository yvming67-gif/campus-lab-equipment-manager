# 云端演示部署

网页与现有小程序接口由同一Django应用提供。这里部署含模拟数据的共享演示环境，不接入学校真实身份或消息，不将其表述为真实校园生产系统。现有Windows本地启动方式保留。

## 架构与费用边界

采用Render免费Web Service运行Waitress、Django及同容器业务任务；Neon保存PostgreSQL 17和私有S3兼容附件。只创建Free套餐，不需要先购买域名。云端运行配置在config/cloud_settings.py，默认本地配置不改。

Render免费服务闲置15分钟会休眠，下一次访问唤醒通常约1分钟；休眠期间提醒和逾期后台扫描也暂停，恢复后按既有幂等规则补扫。这不能满足全天候通知时限，也不能把休眠后的等待计为已达成3秒性能指标。限制及额度以[Render官方免费说明](https://render.com/docs/free)为准，访问日期2026-10-22。

数据库和附件放在Neon，不保存在Render临时文件系统。Neon的免费计算、空间、流量和恢复额度以账号控制台为准；官方资料存在更新批次差异，不在这里承诺无限额度。[官方方案说明](https://neon.com/docs/introduction/plans)、[对象存储入门](https://neon.com/docs/storage/get-started)、[认证配置](https://neon.com/docs/storage/authentication)，访问日期2026-10-22。超额、配额暂停或服务商故障仍可能使演示不可访问。

## 一、创建Neon项目

1. 使用项目所有者的GitHub账号注册Neon，项目名campus-lab-demo。
2. 区域AWS US East 2 (Ohio)，PostgreSQL 17，数据库名neondb。
3. 开启Object storage，存储桶campus-lab-evidence，访问级别Private。
4. Functions、AI gateway、Realtime、Better Auth保持关闭；套餐Free。
5. Connect窗口中选择数据库连接，关闭Pooled connection，使用Direct连接。迁移和启动锁需要会话语义，不使用事务池连接串。
6. 在Storage连接标签选择S3客户端或Parameters，取得S3端点、Access Key ID、Secret Access Key及Region。凭据需要storage:read和storage:write权限。

连接串和存储密钥只在Neon与Render控制台之间复制，不发送聊天、不写入GitHub、不截图展示。Neon API Key并不是S3 Secret Access Key，两者不能互换。

## 二、使用Render蓝图

[从本仓库创建Render演示服务](https://render.com/deploy?repo=https://github.com/yvming67-gif/campus-lab-equipment-manager)

选择自己的免费工作区与main分支，确认Web Service为Free。render.yaml已经配置Python 3.13系列、Ohio区域、构建、启动和健康检查；DJANGO_SECRET_KEY及MOCK_IDP_KEY由Render生成。不要更换为Static Site或GitHub Pages，当前项目需要后端和数据库。

|环境变量|来源与填写方式|
|---|---|
|DATABASE_URL|Neon的Direct PostgreSQL连接串，保留sslmode=require及channel_binding参数；仅填URL，不含psql命令或外层引号|
|AWS_ENDPOINT_URL_S3|Neon Storage提供的完整HTTPS端点，不是数据库主机|
|AWS_ACCESS_KEY_ID|Storage的S3 Access Key ID|
|AWS_SECRET_ACCESS_KEY|Storage的S3 Secret Access Key，不是Neon账户API Key|
|AWS_REGION|us-east-2|
|CAMPUS_STORAGE_BUCKET|campus-lab-evidence|
|DJANGO_SETTINGS_MODULE|蓝图设为config.cloud_settings|
|DEMO_MODE|蓝图设为1，仅模拟身份与模拟投递|

确认必填变量已填后再部署。构建安装固定依赖并执行collectstatic；启动序列化执行迁移、仅空库初始化、检查私有桶访问并补扫业务任务。随后启动网页和后台两个受监督子进程；任一异常退出会停止另一进程，由平台重启整个服务，避免网页假装正常而后台早已停止。

平台提供RENDER_EXTERNAL_HOSTNAME，程序自动设定精确ALLOWED_HOSTS及HTTPS CSRF来源。实际域名由Render分配，以服务控制台显示为准，不预先宣称某个地址已上线。

## 三、访问与演示

部署为Live后访问控制台给出的HTTPS URL。默认模拟账号student、student2、teacher、admin、tech、sysadmin、director，模拟密码Demo@2026。这些是公开演示身份，不是学校账号；不同访问者会共同操作同一批模拟数据。不要上传真实学生材料、联系方式或真实设备责任证据。

登录后验证查询、普通设备确认、受限设备与场地待审、审批、借还、场地交接、异常、维修与独立验收。附件仍通过原有权限检查后的/evidence/编号/下载，私有桶不改为公开，不把对象地址直接放入普通列表。

重部署时只在空库初始化，保留已停用账号、角色变更、预约和审计历史。存储是持久化位置，不是自动备份；不能将它当成误删后的恢复保证。

## 四、验收与维护边界

- 本地/CI可检验URL和密钥必填、TLS、精确主机名、私有存储选项、静态收集、进程相互退出、HTTPS身份回调与CSRF。
- 真正上线后还需在目标地址检验页面样式、各角色登录、预约和审批、附件上传下载及未授权拒绝、服务重启后的数据库和附件留存、休眠唤醒与后台补扫。这些不能被离线配置测试替代。
- 原本地备份工具依赖本地PostgreSQL运行信息和媒体目录，不能直接宣称已经支持Neon私有对象存储的云端一致性归档。云端RPO/RTO及数据库与附件的联合恢复尚需另行完成演练；课程本地备份恢复证据仍限本地环境。
- Neon控制台的分支、恢复功能及Storage快照条件按官方说明核实。重要演示前保留独立导出，恢复到新分支或新库后核对预约、交接、异常、审计、附件摘要和会话失效，不能只看页面可打开。
- 小程序的原生微信容器、合法域名、AppID、隐私配置和发布仍需单独验证；网页上线不等于小程序已正式发布。

如需稳定随时打开、持续后台调度和明确恢复目标，应在确认预算后切换常驻计算、独立任务和经演练的备份安排，不通过外部保活请求掩盖免费服务的休眠限制。
