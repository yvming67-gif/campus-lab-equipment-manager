# 整改与复验计划

本轮只开展全面核查与GitHub首页优化，业务代码保持输入版本。以下为有证据的后续整改顺序，不将建议写成已实现功能。

## 第一阶段 异步与任务一致性

优先处理AUD-0101、0102、0103、0104、0112：按会话代次处理失效，按草稿归属清理请求键，详情/取消响应保持版本单调，通知失效请求必须结束loading，投递回写验证领取代次。每项先保存当前反例，再改成正确行为断言；补旧成功/新失败和旧失败/新成功两种顺序。业务状态与通知provider接受结果分开，不因显示修复伪造真实送达。

## 第二阶段 字段与管理入口

处理原AUD-0009四个新入口、AUD-0106、0107，以及原AUD-0018/0088遗漏。统一ASCII十进制和数据库范围校验；日期加一天先验证可表示边界；投递列表与人工联系共享正确渠道和管理范围。重点验证普通用户、跨实验室、正式/演示模式、重复请求和合法值，不能只补一个示例。

## 第三阶段 反馈和材料改善

处理AUD-0111的三个列表错误/空态区分，再按实际价值安排0108、0109、0110。图形路线0105和局部余白0114可在正式材料下一次编辑时局部处理，需重渲染并核对目录、图源边集合，不缩小图中文字或为了对齐任意增加角色。

## 第四阶段 业务决策与实际接入

先确认AUD-0113当天临时关闭与事实更正的统计口径，再决定有效时点或报表快照方案。原真实身份、消息、独立备份、微信正式发布及学校制度保持独立待验条件；有代码或本地替身不意味着外部能力可关闭。

## 关闭条件

每个稳定编号保留原判断与失败证据，补充修改位置、提交、正确行为反例、相关回归和剩余限制后再关闭。优化建议需记录是否采纳及理由，证伪保留，不能直接删除。修复后重算总台账、当前索引和状态统计，区分代码确认、本地运行、实际云端与手机反馈；最后再做独立复核。
