## 失败、修订与证据边界

1. 用户要求真实图片后，改为核对高校公开实拍；生成的素材未放入项目。两处原图片404、若干类别不符的候选均排除，不把失效页或不相符仪器当作对应照片。
2. 本机原全局浏览器路径失效，使用npm缓存中的同一工具恢复；来源解析最初缺少bs4，改用标准库；GBK网页按原编码读取。工具错误不算业务缺陷。
3. 最初网页脚本将两个详情地址错写成/resource/，返回404却未被其错误识别条件拦截；该尝试不计入最终20观察。按core/urls.py改为/resources/，增加有效页面及角色断言后重新完成。旧尝试留在私有web-first-route-attempt.json。
4. 第一次断图测试命中浏览器已有缓存，没有触发error，等待超时；增加带查询参数的新请求并阻断实际图片请求后，真实error触发。重开本任务浏览器清除旧会话与路由，避免把旧会话当游客。
5. 独立复核发现断图区域仍保留原图坏链接AUD-0132；禁用该图片链接、改无障碍标签后再次执行真实网络失败，验收通过。来源链接保持可用。
6. 微信首次原生尝试出现page node not found，随后读到登录页明确的连接超时。不能仅据此认定为JSON导入、图片或免费冷启动的根因；原生错误与截图检查原始记录保留。为降低运行时差异，目录使用可编译JS模块并与JSON自动核对，但没有把该兼容调整冒充已证实根因修复。
7. 首次重开项目后连接自动化端口过早失败，窗口就绪后重连。连接本地真实后端后原生图片及断图检查完成；随后官方wx.request也证实云端公开登录/退出可达。此结果不抹去之前超时，不承诺以后不会超时。
8. 内联脚本的PowerShell引用和一次相对工作目录曾使样式接入命令未执行；改用确定路径脚本完成。最终编译及视觉核对基于已接入样式的文件。

本轮未进行Android真机、iPhone、正式上传/体验版/发布或名称审核核实；原生模拟器机框外观不等于iPhone验收。正式Word正文与模型未修改，不以界面照片为依据变更学校业务制度。部署、最终云端包与远端CI结果见后续发布记录。
