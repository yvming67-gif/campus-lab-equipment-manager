# 演示操作说明

使用[云端网站](https://campus-lab-equipment-manager.onrender.com/login/)或在本机独立运行。两种环境分别保存模拟数据。网页所有角色都从同一入口登录。云端学生与教师使用公开演示密码，已启用的岗位账号使用部署方私下分发的各自密码。本机模拟账号统一使用演示密码。以下人员、设备和业务均为模拟示例。

1. 打开网页登录入口，选择 `student`、`student2` 或 `teacher`，输入 `Demo@2026`。体验管理角色时先退出，再选择相应账号登录。本机可双击项目根目录“启动演示.cmd”，访问启动窗口显示的地址。
2. 用student查看资源目录。选择普通“数字示波器”，预约未来14天内同日08:00至20:00的30分钟整数时段，填写用途。应直接显示“已确认”。可在开始前取消。
3. 以实验室管理员 `admin` 登录并审核受限设备申请。不同申请可以竞争，批准时服务端再次检查条件。
4. 用 `teacher`申请整间实验室并填写人数，再由`admin`审核。场地申请不会自动借出室内设备；学生申请场地应被拒绝。
5. 本机现场交接可先运行[运行指南](运行指南.md)中的 `prepare_demo` 命令，只在本地模拟库创建场景。再用`admin`打开本机已确认记录。设备借出现场编号为`S-DEMO-02`、标签`EQ-SEN-01`；核对配件、到场及办理时间后借出，再逐件办理归还。无借出、标签不符、缺件与逾期分别处理，不能伪造正常凭据。
6. 场地交接由`admin`登记负责教师编号`T-DEMO-01`、人数和实际开始，结束时记录场地检查结果。场地与设备使用有独立凭据。
7. 异常报告先形成可追踪记录。普通且无关联使用事实的报告先由`admin`核实；安全报告、有关联责任事实的异常及核实确认按既有分级规则阻断，不将所有报障一律隔离。需要维修时`admin`创建工单并指派`tech`；维修人员接单、追加过程、提交结果后为“待验收”，由具备权限且未实际参与本工单维修的管理员复测验收。验收不通过继续维修；其他异常或停用限制仍在时不能恢复资源。
8. `sysadmin`可修改预约参数与模拟消息失败开关。外部服务失败时，站内业务结果仍保留，最多重试3次（1、5、15分钟间隔）。失败任务可追加人工联系说明；后台需保持运行。
9. `director`可查看授权范围内的资源报表和审计。实际利用率按历史正常开放时数计算，不把预约计划当成已使用。
10. 本机停止网页在启动终端按Ctrl+C；数据库可单独停止。本机启动器的后台在具备runtime.json时每23小时尝试备份，数据和归档保存在私有.local目录，重启不清空。云端数据保存在Neon数据库和私有对象存储，Render临时目录不能当作持久备份；免费实例休眠期间任务暂停，唤醒后补扫。真实云端联合备份与恢复仍待独立演练，不能用本机自动备份周期代替。

`seed_demo` 新装会创建3个演示管理单元、6间演示场地、9项演示设备和7个模拟账号；其中一项固定设备关联演示场地，另有一间场地以维护中状态展示不可预约情形。种子命令只创建缺失的演示记录，不清空或覆盖已有预约、审计、用户及自定义资源。真实学校制度、培训证明、节假日安排、校园认证和消息提供方未接入。

## 如何审核他人的预约

普通设备通过规则校验后自动确认。受限设备及整间实验室需要人工审核，整间实验室由教师申请。审批由拥有目标实验室管理范围的实验室管理员承担。系统管理员负责角色与范围配置，实验室管理员也不能审批本人申请。

1. 在同一环境用学生或教师账号提交受限设备或场地申请，确认状态为“待审核”，记下预约编号。
2. 退出后，从同一网页登录入口选择实验室管理员 `admin`。云端使用该账号的独立密码，本机使用演示密码。手机浏览器也可办理审批。
3. 从工作台打开“待审核申请”，按等待时间、编号、申请人或资源定位记录，进入详情并选择“审核预约”。
4. 查看“审批前核对”的检查时间、资格、配额、开放条件与冲突；这些只是当前快照。核对用途、申请人、时段及资源条件，选择“通过”“驳回”或“要求补充说明”，填写“操作原因或说明”后提交。补充说明不构成批准，预约仍为待审核。
5. 批准前系统重新检查资格、开放条件、配额和冲突。待审核不占资源时段，不代表承诺保留。校验未通过时显示原因，不能强行批准；发现并发变更时按提示刷新后核对。
6. 成功通过后显示“已确认”，驳回后显示“已驳回”；审批人、时间、原因、状态变化及申请人的站内通知由服务统一保存。申请人在小程序重新打开详情或查看通知核对结果。确认后仍需现场办理借出或入场。

看不到待审记录或“审核预约”时，核对当前登录角色、预约状态、申请人及管理员的实验室管理范围，并确认申请和审批发生在同一环境。

以上路径和权限对应`core/workbench.py`的待审队列、`templates/booking.html`的审核入口、`core/forms.py`的审核表单和`core/services.py`的`approve`事务服务。当前内容按代码核对，审批决定只由有权操作人提交。

## 设备借出、异常归还和维修验收

以下操作使用同一环境中的一笔模拟预约，网页各角色从同一登录页进入。使用各自浏览器窗口或退出后切换账号，保留预约详情地址供其他有权岗位查找。

| 顺序 | 账号与操作 | 预期结果 |
| --- | --- | --- |
| 1 | 专用学生 `student_lab` 在资源目录选择全画幅摄影套装 `EQ-CAM-01`，预约可交接时段 | 状态为待审核，记录预约编号。公开账号的“我的预约”中看不到这笔记录 |
| 2 | 实验室管理员 `admin` 在待审核申请中打开该笔预约，核对后通过 | 状态为已确认，申请人收到通知 |
| 3 | 在预约允许领取的实际时段，用 `admin` 办理设备借出，借用人编号填写 `S-DEMO-LAB`，设备标签填写 `EQ-CAM-01` | 形成借出凭据，状态为使用中 |
| 4 | `admin` 办理归还，核对实际配件，登记“运行异常”并填写模拟检查情况 | 形成归还凭据和关联异常 |
| 5 | `admin` 从异常详情创建工单并指派 `tech` | 维修人员可在工作台看到自己的待处理工单 |
| 6 | `tech` 开始处理并提交模拟维修结果，`admin` 核验并通过 | 工单关闭，异常结案。资源无其他限制时恢复服务 |
| 7 | `director` 在报表和审计页核对实际交接、维修和验收记录 | 有权查看统计及审计记录 |

现场借出须处于允许领取时段。选时前核对设备没有其他待履行安排，创建维修工单会按正常业务规则处理同资源的未来预约。共享云端的规则和排期可能受其他模拟操作影响。系统设置练习优先在本机进行，避免修改共享云端的开放日历和账号授权。本机初始环境可按同一流程用 `student` 登录，现场借用人编号改用 `S-DEMO-01`。

教师可在同一登录页使用已开通的 `teacher_lab`，单独申请整间实验室。若需要在现场登记其开始使用，负责人编号填写 `T-DEMO-LAB`。实际是否可选由资源日历和冲突检查决定。

## 选时、补充说明与异常报告

以下路径对应仓库代码 `4d834d0` 中的网页与小程序实现；在线演示未公开运行提交号，小程序需使用微信后台实际上传的版本。GitHub更新不会自动替换手机缓存的预览包。2026年11月6日记录的开发版/体验版状态不证明包含 `4d834d0` 的新包已上传或通过真机复验。

1. 查询资源时分别阅读服务状态、实物状态、审批方式和目标时段结论。未选择时段时，服务正常不代表目标时间已经被保留。
2. 打开设备详情，选择日期及使用时长，查看候选条目的不可选原因和检查时间。选择可申请条目后，核对下方申请表起止时间、用途、资源及确认方式；提交时仍实时检查。场地仅教师可申请，学生无可用申请入口。
3. 本人待审核预约在详情提供“补充说明”。管理员“要求补充”后仍是待审核，申请人可在网页或新小程序追加说明；原说明和决定不覆盖。小程序若结果未知，先核对原操作，恢复原内容或以同请求重试，不能通过改内容重复提交。
4. 预约详情显示下一步负责岗位及登记的交接地点。地点未登记时按提示联系现场管理员；未结束的实际使用不会因计划到期而被伪造为归还或离场。
5. 小程序可从资源或本人预约进入“报告资源异常”，选择损坏、缺件或运行/场地异常，填写具体情况和发现时间。仅提交文字；紧急现场事件应立即联系现场管理人员，不将文字提交等同于即时响应或自动定责。普通无关联报告先待核实，其他阻断按原有分级服务判断。
6. 小程序进度与沟通各显示最近100条，超过时提示总数和范围；完整历史到网页详情查看。站内通知和外部投递状态不同，通知失败不撤销已成功保存的业务。

本期8页模板编译、模拟客户端和真实本地API联调分别有[验证记录](验证说明.md)。新版微信容器、Android本期新流程、名称审核及正式发布仍需独立证据；iPhone继续延期。
