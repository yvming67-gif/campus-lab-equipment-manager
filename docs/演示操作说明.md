# 演示操作说明

本项目可使用已有[云端演示](https://campus-lab-equipment-manager.onrender.com/)或在本机独立运行。两者各自保存模拟数据，不能把本机创建的预约当作云端已有记录。2026-11-10 对 Render 进行只读复核：健康检查返回就绪，公开身份页只列出 `student`、`student2` 和 `teacher`，未列出管理账号。应用不公开线上部署提交号，因此这证明了当日观察到的线上行为，不证明某个精确 Git 提交已部署。实验室管理员、维修人员、中心主任和系统管理员的完整流程只在本机隔离演示环境中验证。以下人员、设备、维修事实和业务均为模拟示例；本机专属命令不得对共享云端数据执行。

1. 云端演示直接打开上述地址，选择`student`、`student2`或`teacher`，输入公开演示密码`Demo@2026`。完整管理流程请双击项目根目录“启动演示.cmd”，默认 http://127.0.0.1:8000，端口占用时以启动窗口实际地址为准；本机演示数据与共享云端相互独立。
2. 用student查看资源目录。选择普通“数字示波器”，预约未来14天内同日08:00至20:00的30分钟整数时段，填写用途。应直接显示“已确认”。可在开始前取消。
3. 在本机角色选择器切换到实验室管理员`admin`审核受限设备申请；不同申请可以竞争，批准时服务端再次检查条件。公开云端不开放管理账号，审批演示请使用本机隔离环境。
4. 用本机`teacher`申请整间实验室并填写人数，再由`admin`审核。场地申请不会自动借出室内设备；学生申请场地应被拒绝。
5. 本机现场交接可先运行README所述的`prepare_demo`命令，只在本地模拟库创建场景。再用`admin`打开本机已确认记录。设备借出现场编号为`S-DEMO-02`、标签`EQ-SEN-01`；核对配件、到场及办理时间后借出，再逐件办理归还。无借出、标签不符、缺件与逾期分别处理，不能伪造正常凭据。
6. 场地交接由`admin`登记负责教师编号`T-DEMO-01`、人数和实际开始，结束时记录场地检查结果。场地与设备使用有独立凭据。
7. 异常报告先形成可追踪记录。普通且无关联使用事实的报告先由`admin`核实；安全报告、有关联责任事实的异常及核实确认按既有分级规则阻断，不将所有报障一律隔离。需要维修时`admin`创建工单并指派`tech`；维修人员接单、追加过程、提交结果后为“待验收”，由具备权限且未实际参与本工单维修的管理员复测验收。验收不通过继续维修；其他异常或停用限制仍在时不能恢复资源。
8. 本机`sysadmin`可修改预约参数与模拟消息失败开关。外部服务失败时，站内业务结果仍保留，最多重试3次（1、5、15分钟间隔）。失败任务可追加人工联系说明；后台需保持运行。
9. 本机`director`可查看授权范围内的资源报表和审计。实际利用率按历史正常开放时数计算，不把预约计划当成已使用。
10. 本机停止网页在启动终端按Ctrl+C；数据库可单独停止。本机启动器的后台在具备runtime.json时每23小时尝试备份，数据和归档保存在私有.local目录，重启不清空。云端数据保存在Neon数据库和私有对象存储，Render临时目录不能当作持久备份；免费实例休眠期间任务暂停，唤醒后补扫。真实云端联合备份与恢复仍待独立演练，不能用本机自动备份周期代替。

`seed_demo` 新装会创建3个演示管理单元、6间演示场地、9项演示设备和7个模拟账号；其中一项固定设备关联演示场地，另有一间场地以维护中状态展示不可预约情形。种子命令只创建缺失的演示记录，不清空或覆盖已有预约、审计、用户及自定义资源。真实学校制度、培训证明、节假日安排、校园认证和消息提供方未接入。

## 本机隔离演示：如何审核他人的预约

以下管理员流程仅用于本机隔离演示。2026-11-10 的线上身份页复核只显示学生和教师演示账号；管理审批入口仍仅在本机隔离环境演示。普通设备通过规则校验后自动确认，不产生人工待审任务。高价值、危险或要求培训资格的设备，以及整间实验室场地，需要人工审核；只有教师可以申请场地。

人工审核由拥有目标实验室管理范围的实验室管理员承担。本机模拟身份`admin`仅用于隔离环境；公开云端是否已移除管理身份仍待部署后复验。系统管理员`sysadmin`负责角色与范围配置，不会自动获得业务审批权；学生、教师、维修人员和只读负责人也不能仅凭各自角色批准预约。管理员不能审批本人申请。

1. 在本机网页环境中以申请人身份提交受限设备或场地申请，确认状态为“待审核”，记下预约编号。普通设备的“已确认”记录不需要再审。本机与云端数据互不相通；线上角色权限需以部署后检查结果为准。
2. 审批人在本机启动环境的浏览器模拟身份入口选择`admin`登录。可在电脑或手机浏览器操作；当前小程序没有管理员审批界面。不得把本机角色切换说明理解为云端公开角色已开放。
3. 从本机工作台进入“待审核申请”，或打开本机`/bookings/?queue=review`。默认按等待时间优先展示，也可切换排序；根据编号、申请人及资源定位记录，进入详情，选择“审核预约”。
4. 查看“审批前核对”的检查时间、资格、配额、开放条件与冲突；这些只是当前快照。核对用途、申请人、时段及资源条件，选择“通过”“驳回”或“要求补充说明”，填写“操作原因或说明”后提交。补充说明不构成批准，预约仍为待审核。
5. 批准前系统重新检查资格、开放条件、配额和冲突。待审核不占资源时段，不代表承诺保留。校验未通过时显示原因，不能强行批准；发现并发变更时按提示刷新后核对。
6. 成功通过后显示“已确认”，驳回后显示“已驳回”；审批人、时间、原因、状态变化及申请人的站内通知由服务统一保存。申请人在小程序重新打开详情或查看通知核对结果。确认后仍需现场办理借出或入场。

本机隔离演示看不到待审记录或“审核预约”时，先核对是否在本机环境登录`admin`、记录是否仍为待审核、是否为本人申请，以及管理员是否有目标实验室管理范围。当前公开云端未完成此次权限变更复验，不用云端记录验证管理员审批流程，也不要尝试通过切换网址参数扩大权限。角色与管理范围的变更由本机隔离环境中有权系统管理员在“管理中心 → 用户与授权 → 维护授权”办理。

以上路径和权限对应`core/workbench.py`的待审队列、`templates/booking.html`的审核入口、`core/forms.py`的审核表单和`core/services.py`的`approve`事务服务。当前内容按代码核对，审批决定只由有权操作人提交。

## 选时、补充说明与异常报告

以下路径对应2026年11月5日本期代码；在线演示需先核对实际部署版本，小程序需使用重新编译的新包。GitHub更新不会自动替换手机缓存的预览包。

1. 查询资源时分别阅读服务状态、实物状态、审批方式和目标时段结论。未选择时段时，服务正常不代表目标时间已经被保留。
2. 打开设备详情，选择日期及使用时长，查看候选条目的不可选原因和检查时间。选择可申请条目后，核对下方申请表起止时间、用途、资源及确认方式；提交时仍实时检查。场地仅教师可申请，学生无可用申请入口。
3. 本人待审核预约在详情提供“补充说明”。管理员“要求补充”后仍是待审核，申请人可在网页或新小程序追加说明；原说明和决定不覆盖。小程序若结果未知，先核对原操作，恢复原内容或以同请求重试，不能通过改内容重复提交。
4. 预约详情显示下一步负责岗位及登记的交接地点。地点未登记时按提示联系现场管理员；未结束的实际使用不会因计划到期而被伪造为归还或离场。
5. 小程序可从资源或本人预约进入“报告资源异常”，选择损坏、缺件或运行/场地异常，填写具体情况和发现时间。仅提交文字；紧急现场事件应立即联系现场管理人员，不将文字提交等同于即时响应或自动定责。普通无关联报告先待核实，其他阻断按原有分级服务判断。
6. 小程序进度与沟通各显示最近100条，超过时提示总数和范围；完整历史到网页详情查看。站内通知和外部投递状态不同，通知失败不撤销已成功保存的业务。

本期8页模板编译、模拟客户端和真实本地API联调分别有[验证记录](验证说明.md)。新版微信容器、Android本期新流程、名称审核及正式发布仍需独立证据；iPhone继续延期。
