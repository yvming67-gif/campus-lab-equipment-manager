# 访问入口与预约流程

本轮从 Andrew Dental 的公开首页和演示工作台提取了两项设计思路。首屏用清楚的主行动和分类入口承接访客目标。资源详情和结果页分别回答选什么、何时使用、接下来谁负责。实际查阅了参考站的手机导航、门诊详情、三步指引、预约列表与日程、牙椅资源和资质目录。

|改进|实现与验证目标|
|---|---|
|访问入口|公开页面分为进入系统、设备、教室三个入口。受保护目录先登录，完成后继续进入原分类。跳转限于指定的站内资源目录。|
|角色登录|使用原生单选卡片展示当前可登录账号及职责。公开演示账号、已配置岗位及各自授权沿用现有配置。|
|资源卡片|教室显示房间号、位置、容量和当天或所选日期的开放安排。设备显示交接地点、培训要求和确认方式。开放安排和目标时段可用性分别展示。|
|预约步骤|选资源与时段、核对并提交、查看结果与下一步。网页和小程序复用原预约与审批规则。网页结果未知时，同一浏览器标签页保留原请求及输入，可先核对回执并按原内容重试。|

图片仅采用已登记且允许公开展示的对应资源实拍。当前未取得可新增的对应实拍授权。网页无需扫码。微信公开发布、真机及审核状态需要单独验证。

参考：[Andrew Dental 首页](https://andrewdental.top/) · [门诊目录](https://andrewdental.top/explore/clinics) · [预约指引](https://andrewdental.top/#booking)。

## 验证记录

- 隔离 PostgreSQL 的网页实测覆盖教师从教室快捷入口经角色卡片登录并返回教室目录。六间教室都显示开放安排。320、390、768、1440 CSS 像素的教室目录未出现整页横向溢出。
- 使用真实网页表单提交普通设备、受限设备和教室三类申请，分别显示等待现场领取、等待审核和等待审核。核对区显示已填用途与人数。模拟浏览器恢复验证了原内容、编号和回执入口。
- Django 定向回归通过105项，随后补测双端开放日期一致性和回执对象范围，2项通过。小程序128项客户端测试与8页编译通过。独立复核后修正回执恢复、设备交接点和日期摘要问题。
- 微信开发者工具已核对师生登录和六间教室。预约步骤的原生控件计数未得到可用自动化结果。正式版和真机留待单独验证。
