## 三、AUD-0073 后台断连后持续复用失效数据库连接

**类型：** 已确认缺陷。

**严重程度：** 严重。网页进程可能仍然正常，而预约失效处理、提醒及通知投递长期停止恢复。

**证据状态：** 代码确认；主流程隔离运行验证；独立代码与证据复核。

**所属模块及角色：** 后台任务、运行维护；影响申请人、管理员及维护人员。

**发现位置：**

- core/management/commands/run_jobs.py，Command.handle循环及异常处理。
- core/services.py，run_jobs开始处的预约扫描。
- tools/start_cloud.py，子进程存活监督。

**问题及触发条件：** 管理命令是长时间运行的进程，不经过HTTP请求的连接清理边界。原循环发生数据库错误后只记录错误并继续等待，没有关闭失效连接。如果数据库会话在首条扫描查询前被服务器终止，后续循环可能继续复用已经关闭的连接，错误心跳也无法写入。任务进程仍然存活，父进程不会因子进程退出而重启它。

Django官方明确说明，请求周期之外的长进程需要显式清理旧连接或不可用连接。[Django数据库连接说明](https://docs.djangoproject.com/en/5.2/ref/databases/#caveats)

**隔离复现步骤：**

1. 在独立测试数据库初始化模拟预约。
2. 使用另一条数据库连接取得并终止本轮任务扫描自己的后台PID。
3. 让任务执行首条查询。
4. 观察失败后的错误记录与后续循环。
5. 再执行两轮扫描，检查重连、心跳恢复及补扫是否重复。

**预期行为：** 记录本轮错误，清理失效连接；数据库恢复可访问后，下轮重新连接并补扫。不能重复产生失效审计或投递任务。

**原实际行为：** 修复前日志出现OperationalError: the connection is closed，并导致后续心跳读取及测试清理出现连锁错误。独立复核没有将此现象说成真实Neon线上故障。

**根因：** 长循环缺少数据库连接生命周期处理；仅监督进程退出不能识别仍存活但持续复用坏连接的工作进程。

**最小修订：**

- 每轮扫描开始调用close_old_connections()。
- 捕获异常后先关闭连接，再尝试写错误心跳。
- 每轮finally再次清理连接。

**验收与证据：** 新增CloudJobRecoveryTests使用TransactionTestCase及独立psycopg连接，实际终止隔离数据库中的扫描会话。测试断言第一轮记录错误，第二轮恢复扫描并处理预约失效，第三轮重复补扫不增加EXPIRE审计和Delivery数量。

主流程提供的cloud-integration.log显示6项测试通过；修复前的worker-recovery-before.log保留失败过程。独立复核确认测试确实触发服务器端断连，没有仅以模拟异常替代连接终止。辅助运行日志由项目工作区留存，不包含真实云端连接信息；仓库提供可重跑测试及下述摘要用于复核。

**当前状态：** 代码已修订，隔离环境复验通过。真实Neon网络故障及平台恢复场景尚未执行，不计入已完成的外部验收。

## 四、已确认合理的适配

云端配置与原本地配置分开，要求明确的稳定密钥、主机名、数据库连接和存储凭据；没有静默降级到本地数据库或公开附件目录。

启动使用PostgreSQL会话级锁，覆盖迁移与空库初始化，并在finally释放。部署说明明确要求Direct连接，符合该锁需要会话语义的条件。具体Neon角色的迁移权限仍须实际验证。

代理、HTTPS和会话配置相互协调：Waitress监听平台端口，接收指定转发头；Django采用精确主机名、HTTPS来源及Secure Cookie。精确/health/免HTTPS跳转后，数据库失败能够返回503，其他页面仍保留HTTPS跳转。Render将2xx及3xx视为健康结果，因此该区别有实际意义。[Render健康检查说明](https://render.com/docs/health-checks)

附件配置采用私有存储选项、path-style、SigV4及受控下载入口。Neon官方列明支持HeadBucket、对象读写及multipart等当前需要的操作，未发现确定的API选择冲突；这不等于目标桶已经联调成功。[Neon S3兼容性说明](https://neon.com/docs/storage/s3-compatibility)

监督进程能够在任一子进程退出时停止同伴并结束服务，避免只留下网页或后台进程。AUD-0073修订补上了进程仍存活但数据库连接不可用的一种恢复路径。

部署文档没有将持久化位置冒充备份，也没有将免费服务休眠说成持续调度。Render免费服务会休眠并丢失临时文件，当前将数据库和附件放在外部持久化服务中的方向合理。[Render免费服务限制](https://render.com/docs/free)
