**类型**：已确认缺陷

**严重程度**：严重

**判断理由**：网页可能仍正常而后台失效、提醒和通知投递长期停滞，且进程存活监督无法发现；按独立复核提高整改优先级，不表示已经发生线上事故。

**问题描述**：管理命令长循环没有请求边界的连接清理。首条事务外扫描遇到服务端终止连接时，异常处理仍在坏连接上写心跳，下一轮又复用该连接；子进程未退出，监督器无法从退出码发现停滞。

**触发条件**：run_jobs --loop 自己的数据库会话在扫描前断开，数据库随后可建立新连接。真实 Neon 是否发生过此情况未验证。

**预期及依据**：首轮故障不产生部分业务凭据；数据库可恢复时重建连接写错误心跳并在下一轮完成补扫；再次补扫不得重复过期事件及投递任务。依据：任务恢复要求及 Django 长进程连接管理规范。

**实际行为**：修订前真实 OperationalError 后继续复用已关闭连接，错误心跳无法取得；测试还在清理时出现同根因连锁报错。修订后第一轮写错误心跳，第二轮恢复并过期一次，第三轮审计 EXPIRE 及 Delivery 计数不增加。

**证据**：2026-10-22 隔离 PG17.11/TLS：修订前6项中恢复场景失败（同一坏连接还触发tearDown连锁错误）；修订后6项全通过。断连由pg_terminate_backend触发，不是真实云端故障演练。Django https://docs.djangoproject.com/en/5.2/ref/databases/#caveats，访问2026-10-22。
