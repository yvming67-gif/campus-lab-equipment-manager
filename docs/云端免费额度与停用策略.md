# 云端免费额度与停用策略

记录日期：2026年10月22日。目标为仅使用免费额度，额度耗尽后停止相应服务，不授权购买额外用量或升级付费方案。

## 当前状态

- Render服务已使用Free实例；用户先确认Render已保存支付方式，随后确认账单页存在移除按钮，最后明确回复“已经移除”。保留这段状态变化，不将历史上曾绑定支付方式改写为从未绑定。
- Neon最初创建为Free；用户在询问当前Billing／Plans套餐后明确回复“free”，现按用户确认记录为Free。未独立读取私有控制台，也未取得实际剩余额度。
- 支付方式移除属于用户操作确认，尚未独立读取私有账单页面核实；构建费用上限和当前待结算费用亦未独立验证。官方无支付方式时的免费流量停用及停止新构建规则适用于后续额度处理，不代表历史费用已取消，也不代表所有云资源已逐项确认为免费。
- 为减少不必要消耗，已停止大批量线上测试及可能触发Render构建的推送。用户随后要求先完成部署收尾、最后更新GitHub，据此只补做一次3次GET的部署基础检查，未重新部署。纯文档收尾使用[skip render]跳过自动部署；未添加持续保活。现有站点未主动暂停，代理未删除任何服务、数据库、对象或支付方式；支付方式移除由用户自行完成。

## Render的不同额度必须分别处理

1. 免费实例小时耗尽后，平台暂停工作区的免费Web服务至下月。此机制不代表流量也已设置零费用上限。
2. 已保存支付方式时，出站流量超过包含额度可能产生额外账单。官方说明未添加支付方式时会改为暂停免费服务。本轮查阅的免费部署、FAQ及构建文档中，未找到可确认适用于此账户的流量硬性费用上限；这不是对全部后台选项的穷尽断言。
3. 构建分钟可在工作区Settings → Build Pipeline → Set spend limit/Edit设置费用上限。用户已确认移除支付方式，官方无支付方式时停止新增构建的规则是当前依据；未额外设置构建费用上限，不将其写成已生效。若未来需要恢复支付方式，必须先重新核实额外构建支出能否设为0美元及其含义。停止新构建不等于暂停已有网站。
4. 如果平台允许移除支付方式且保留免费服务，可核对移除后的账户状态及额度耗尽行为。移除支付方式不表示既有费用被取消；若账户验证要求保留支付方式，不能保证该路径可用。应先确认界面选项和账户要求，再执行。
5. 邮件告警、应用限流、减少请求或关闭自动部署只能降低消耗，均不能单独证明平台不会收取超额费用。若无法取得可核实的硬性停用保障，严格零超额目标下仍需选择暂停服务或更换具备硬限制的托管方案，不能擅自将风险接受视为授权。

## Neon

保持Free套餐，不升级Launch或Scale。官方套餐说明Free为0美元；计算、网络及存储额度的耗尽行为需按当前套餐分别核对，不能统一写成整个项目自动删除或恢复。计算与网络属于周期额度，存储不是每月自动清零的容量。现有数据库和附件不得为节省额度直接删除。

平台API部分quota字段中的0可能表示取消限制，不能未经核实写入0来表达“禁止花费”。不在本轮引入需要新密钥的额度轮询，也不把周期轮询当作无延迟的账单硬限制。

## 后续核实项

- Render支付方式已按用户回复移除；仍需留意平台是否再次要求账户验证。若要求重新绑定，不擅自恢复支付方式或接受付费升级。
- 剩余流量、构建分钟和免费实例小时；如未来恢复支付方式，必须先重新核实构建和流量的费用限制，不沿用当前无支付方式的停用结论。
- 是否已有待结算费用；若有，单独记录，不与未来支出上限混淆。
- Neon当前套餐已由用户确认为Free；数据库、计算、出站流量及对象存储实际用量仍待验证。

用户确认与独立控制台验证分别记录；未取得的用量及账单证据保持“待验证”。后续继续采用免费演示策略，不购买额外额度、不自动升级或重新绑定支付方式；额度耗尽接受相应服务不可用。无需收集银行卡号、安全码、数据库连接串或任何云服务密钥。
