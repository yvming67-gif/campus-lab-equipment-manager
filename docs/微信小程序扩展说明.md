# 微信小程序扩展说明

## 范围与使用者

新增微信小程序作为学生和教师的访问渠道，提供查询、预约、取消、进度与通知。实验室管理员、维修人员、系统管理员和中心主任继续使用网页。业务参数、审批责任和实际交接规则采用统一需求基线。

七个原生页面包括登录、资源目录、资源预约、本人预约、预约详情、通知中心和个人信息。设备与整间场地分别预约；学生和教师可借设备，仅教师可申请场地；普通设备自动确认，受限设备和场地由管理员审批；待审核不占时段。

正式分析报告使用2.3业务描述，ERD沿用兼容的2.2物理基线，来源和课程假设见逻辑整改目录。本次增加传输接口和用户渠道，页面与原用例按下表对应，不另造一套预约状态。领域模型为36个实体、289个字段、61条物理外键；小程序会话使用Django框架会话表，与既有框架会话一样不列入领域ERD。

## 接口契约

统一前缀：`/api/mini/v1`。请求与响应使用UTF-8 JSON。成功返回`{ok:true,data:...,request_id:...}`；失败返回`{ok:false,error:{code,message,fields},request_id:...}`。`request_id`与审计上下文一致，错误中不输出凭据。

|方法与地址|用途|输入或筛选|
|---|---|---|
|POST `/auth/login/`|模拟登录|username、password；仅课程模式及学生/教师|
|POST `/auth/logout/`|撤销本次小程序会话|专属Authorization头|
|GET `/me/`|本人信息、当前规则与配额|从会话确定本人|
|GET `/resources/`|分页查询资源|q、kind、lab、starts_at、ends_at、page|
|GET `/resources/{id}/`|详情与资源占用时段|可选起止时间、schedule_day、schedule_page；不返回他人的申请人和用途|
|GET `/bookings/`|本人预约记录|q、status、page|
|POST `/bookings/`|提交预约|resource_id、starts_at、ends_at、purpose、participants、request_key|
|GET `/bookings/{id}/`|本人预约详情及审计进度|预约编号对应的内部ID|
|POST `/bookings/{id}/cancel/`|取消本人预约|reason、version|
|GET `/notifications/`|本人通知|page|
|POST `/notifications/{id}/read/`|单条已读|仅本人通知|
|POST `/notifications/read-all/`|全部已读|仅本人的未读记录|

资源/预约/通知列表分页每页20条，返回`items/page/total/has_more`。资源详情占用列表单独每页30条，保留schedule数组并新增schedule_total、schedule_page、schedule_has_more、schedule_day；schedule_day可选YYYY-MM-DD，非法日期/页码返回400及字段提示。按日期筛选仍显示未结束的实际使用，不能因计划结束就假装资源已归还。通知项新增kind_label，预约进度timeline各项的label采用与网页一致的中文事件名称。时间提交为`YYYY-MM-DDTHH:mm:ss`，由服务端按Asia/Shanghai解释；响应时间明确包含`+08:00`。起止时段须一起提供。

错误状态包括400字段或JSON无效、401未登录/失效、403角色不支持、404记录不存在或不可访问、405请求方式错误、409业务规则或并发冲突、413内容过长、415内容类型错误、429演示登录限速、503身份适配器未启用。普通用户访问他人预约或通知统一返回404。

## 身份、事务和边界

模拟身份凭据与网页共用同一独立适配器，业务用户仍没有可用学校密码。登录成功创建两小时有效的小程序专属会话，客户端通过Authorization Bearer头提交；网页Cookie不能作为小程序认证凭据。每次请求重新核对账号状态与角色，权限撤销和账号停用后不能继续访问。

JSON接口单独采用Bearer认证，网页表单的CSRF保护保留。响应不缓存，令牌不进入URL或公开文件。演示登录使用单进程缓存限制错误尝试；正式上线需要适配真实身份和共享限速设施。设置`DEMO_MODE=0`时，本次小程序模拟接口返回503。

创建和取消调用`core/services.py`中的统一事务服务，保留资源排斥约束、资格、配额、逾期与版本检查。重复点击、网络中断后的同内容重试复用请求编号。取消、确认等变化继续生成既有审计与通知，不由前端自行修改状态。

## 验收场景

|编号|给定—当—那么|对应|
|---|---|---|
|MP-AC-01|给定正常模拟学生身份；当登录并查询；那么可取得专属会话与本人配额，网页Cookie不能替代该凭据。|UC-01；QR-03|
|MP-AC-02|给定普通设备和无冲突时段；当在小程序提交；那么后端创建已确认预约，网页可查询同一记录。|UC-03/04；AC-07/08|
|MP-AC-03|给定相同请求编号；当网络重试相同内容；那么返回同一预约，不产生第二条记录。|UC-04；BR-35|
|MP-AC-04|给定受限设备待审核申请；当管理员在网页通过；那么小程序刷新后显示已确认及本人结果通知。|UC-06/08/22|
|MP-AC-05|给定学生身份；当直接调用场地提交接口；那么服务端拒绝，界面隐藏或禁用场地申请。|UC-05；BR-02|
|MP-AC-06|给定教师身份且容量、时段合规；当提交场地申请；那么创建独立的待审核申请，不占用室内设备。|UC-05；BR-02/11/14|
|MP-AC-07|给定本人尚未开始的预约；当填写原因并取消；那么状态更新、时段释放且保留审计；过期版本被拒绝。|UC-07；BR-16/26|
|MP-AC-08|给定他人的预约或通知ID；当尝试查看或修改；那么返回404且数据不变。|UC-06/07/22；BR-29|
|MP-AC-09|给定已收到本人通知；当读取单条或全部已读；那么仅修改本人已读状态，重复操作保持幂等。|UC-22|
|MP-AC-10|给定已登录会话；当账号停用、角色撤销或会话到期；那么后续请求被拒绝并要求重新登录。|UC-01；QR-03|
