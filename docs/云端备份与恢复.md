# 云端联合归档与恢复

适用于现有Django云端演示配置的手动维护工具。它从同一PostgreSQL快照读取业务表计数、附件索引和数据库归档，再通过配置的Django存储读取附件并验证SHA-256。不会调用迁移、清空数据或改写源附件。导出归档不等于恢复成功，也不代表已经有自动异地备份。

## 已验证范围

2026年10月23日在隔离的本机PostgreSQL 17实例上完成3项集成测试：以非文件系统的InMemoryStorage模拟远端存储，导出已借出归还的预约、交接、异常、证据和审计；恢复到全新数据库，逐表核对快照计数、核对附件摘要并确认会话为0。缺失、被改写附件、容量超限和公开源码目录目标均被拒绝。完整192项回归日志见[本批证据](整改/证据/剩余整改-2026-10-23/后端完整回归.log)。这没有访问真实Neon、S3或其他云账号。

## 一、准备可信维护电脑

使用与源库一致的PostgreSQL 17客户端（包含pg_dump、pg_restore），安装requirements-cloud.txt。本机需要能访问源数据库的Direct TLS端点和同一分支的私有对象存储；使用经授权且权限尽量小的凭据。导出快照需要保持源连接，不能用事务池连接串代替Direct连接。

在私有维护终端的进程环境中配置以下变量，值从自己的服务控制台取得，不放进仓库、命令记录截图或聊天：DJANGO_SETTINGS_MODULE=config.cloud_settings、DEMO_MODE=1、DATABASE_URL、DJANGO_SECRET_KEY、MOCK_IDP_KEY、ALLOWED_HOSTS、AWS_ENDPOINT_URL_S3、AWS_ACCESS_KEY_ID、AWS_SECRET_ACCESS_KEY、AWS_REGION、CAMPUS_STORAGE_BUCKET。字段含义见[部署说明](云端部署.md)。此配置仅供独立维护进程读取，不启动Web或后台任务。不要将源凭据写进下面的命令参数。

## 二、导出一次联合归档

以下均在项目根目录运行，示例路径和文件名应换成维护电脑自己的位置。目标目录应位于项目外，且仅授权维护人员可读；目标文件不能已经存在。

```powershell
python tools/backup_cloud.py --pg-bin "C:/PostgreSQL/17/bin" --output "D:/campus-backups/campus-20261023.zip" --maximum-mb 100
```

归档包含database.dump、manifest.json及快照引用的证据文件；排除django_session数据。manifest记录数据库/附件摘要、源快照表计数及创建时间，导出回执明确restore_verified=false。默认限制数据库导出大小与附件总字节为100MiB，可在2GiB以内显式调整；超限或任意附件摘要不符时不发布归档。此容量保护是工具边界，不是服务商费用或剩余额度检查。

导出可能消耗数据库计算和网络流量，只在免费额度允许时执行。导出完成后将归档与其SHA-256回执保存在独立受控位置；同一电脑另一目录不等同于异地副本。归档包含账号标识、业务和审计内容，应限制访问并按学校确认的保留策略处理，不能上传公开GitHub。源附件在导出期间须保持不可覆盖；如发生管理员删除、摘要不符或网络故障，保留失败记录并重新导出，不把不完整结果记成成功。

## 三、恢复到独立目标

先在维护终端切换到目标本地PostgreSQL凭据，使用PGPASSWORD等目标进程环境变量；不要误用源云库连接。目标用户需要创建数据库权限。目标数据库必须不存在，附件目标必须不存在或为空。以下命令不需要源数据库在线，也不导入Django云配置。

```powershell
python tools/restore_archive.py --archive "D:/campus-backups/campus-20261023.zip" --pg-bin "C:/PostgreSQL/17/bin" --target-db campus_restore_20261023 --media-dir "D:/campus-restore/20261023-media" --host 127.0.0.1 --port 5432 --user campus_restore
```

只恢复可信来源归档。工具在还原前检查归档结构及摘要，拒绝覆盖已有数据库或非空附件目录，数据库导入使用单事务；按清单核对全部表计数、附件摘要以及会话排除，输出restore-receipt.json。失败会保留新建目标供诊断，不自动删库，不把部分目标作为可用环境。

恢复回执只是结构与摘要通过的证据。还需在隔离应用中抽查关键预约到审批、交接、归还、异常、维修和审计的关联、角色权限与附件下载；确认新登录可用且原有效会话不可用，记录恢复耗时和可恢复时间点。只有这些通过后才讨论切换服务，不允许为了演练覆盖正在运行的库。当前工具不自动把恢复附件回传目标S3桶；回迁/新桶切换需单独受控验证。

## 四、仍待实际完成

真实Neon Direct TLS快照导出、同一私有桶附件读取、独立副本留存、断开源环境后恢复及业务抽查尚未执行，因此AUD-0030仍开放。不自动写“备份已验证”健康标记，不隐去operations/health中尚未达成的恢复条件。RPO/RTO、频率、保留、费用和责任人需结合实际演示/试点安排确认。

可复现本地集成检查：在拥有隔离数据库创建权限的测试配置中设置CAMPUS_TEST_PG_BIN指向匹配的客户端目录，再执行python manage.py test core.backup_tests --noinput。未设置该变量时这3项明确跳过；标准CI未配本机客户端时不能把跳过当作恢复通过。

## 方法依据

- PostgreSQL 17 [pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)：自定义格式与一致快照导出能力；本项目额外校验附件与同快照元数据，数据库工具本身不备份S3对象。
- Django 5.2 [File storage API](https://docs.djangoproject.com/en/5.2/ref/files/storage/)：通过配置存储读取文件，避免依赖远端存储不存在的本地文件路径；InMemoryStorage仅为测试替身。
