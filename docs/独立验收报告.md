# 独立验收报告

验收日期：2026年10月19日。项目：校园实验室设备预约与借用管理系统。产品基线：`4b1ef5e`；后续验收文档提交不改变本次产品测试结论。

## 1. 结论与适用范围

本次对课程演示项目开展独立代码审查、隔离副本运行、数据库测试和真实浏览器验收。76项业务测试、11项启动及环境隔离测试、1项真实HTTP负载测试分别通过；19个浏览器场景通过；含模拟证据的备份与隔离恢复核对通过。未发现阻止本次课程本地演示交付的未关闭问题。

该结论适用于文档规定的Windows x64、Python 3.13及模拟业务环境。验证未覆盖所有Windows 10/11硬件和系统配置，适用范围以本次记录的环境为准。首次下载、Python安装、网络访问和微软运行库仍是运行前提。

## 2. 环境与证据组织

独立运行环境为Windows 11（10.0.26200）、AMD64、Python 3.13.12、独立虚拟环境、Django 5.2.18和PostgreSQL 17.11。副本放在包含中文与空格的本地目录，采用与原演示实例不同的数据库和网页端口。业务测试及负载测试分别创建、销毁独立测试数据库；恢复演练创建新命名数据库，没有覆盖演示库。

所复验副本来自不含`.local`及`.venv`的源码包。初装记录显示其独立下载并建立依赖、数据库、密钥和模拟数据；独立验收者重新启动该副本，并自行执行本报告所列业务、负载、配置隔离、模型及恢复检查。网页抽查使用真实Chromium浏览器及实际HTTP表单提交，未以静态截图替代交互。

GitHub的另一台Windows Server 2022 x64运行器另行执行了中文与空格目录中的实际首次安装、第二次启动、11项工具检查及真实备份恢复；Linux运行器执行业务和需求追踪检查。[产品基线对应的公开运行记录](https://github.com/yvming67-gif/campus-lab-equipment-manager/actions/runs/39147064403)可供核对。Windows Server运行记录用于独立安装复验，不等同于穷尽所有Windows 10/11配置。

公开、可复现的入口为`core/tests.py`、`core/benchmark_tests.py`、`tools/test_startup.py`、`tools/validate_registry.py`和`tools/backup_restore.py`。原始运行日志和受控探针留存在本地验收工作目录；数据库、证据备份、会话和私有配置不上传公共仓库。

## 4. 业务、并发与权限验收

独立完整执行`python manage.py test core.tests --noinput`，76项通过，用时30.350秒。覆盖范围包括：

- 普通设备自动确认，受限设备和场地人工审核，待审核不占资源时段，批准时再次检查。
- 未来窗口、时间先后、30分钟粒度、开放时段、时长、培训资格、人数、每类配额和同一时段设备数量。
- 本人取消、重复请求幂等、不同内容复用请求号拒绝、版本冲突及临界结束时刻禁止开始使用。
- 身份和标签不匹配、配件异常、正常归还、无借出记录、逾期、损坏与缺件、场地开始和结束、异常隔离及维修验收。
- 消息失败不回滚业务、投递重试和提醒去重、事务中途失败回滚、受控证据访问及摘要、身份票据重放和CSRF。
- 角色与实验室范围、本人数据隔离、授权撤销、审计数据库更新/删除阻止，以及实际利用率与计划占用分列。
- 100组双用户并发竞争、并发审批、跨资源个人配额串行检查和数据库区间排斥约束。

另外建立了一个私有受控并发探针，检查日历修改与新预约确认之间是否可能穿透。实际结果是预约事务被实验室行锁串行，修改提交后按新日历拒绝越界预约；该候选风险经实测排除。`select_related('lab')`连接查询的行锁在此承担作用，不能只看到资源锁语句便认定实验室未加锁。

11项`tools/test_startup.py`独立执行全部通过，用时2.117秒。三个测试批次分别执行，以上时间不是一次总运行时间，也不是完整代码分支覆盖率证明。

## 5. 真实浏览器验收

以下19项均通过实际页面和正常业务入口完成，覆盖学生、教师、实验室管理员、维修人员、系统管理员和中心主任：

1. 学生普通设备自动确认。
2. 本人取消未来预约并留痕。
3. 受限设备进入待审核。
4. 学生场地预约资格限制。
5. 普通用户不能读取他人预约详情。
6. 待审核不占时段，第二份竞争申请可保存。
7. 管理员在线批准受限设备。
8. 后审批竞争申请被二次冲突检查拒绝。
9. 教师场地预约提交待审核。
10. 场地人工审核确认。
11. 场地预约不会自动占用室内设备。
12. 学生审计和管理入口拒绝越权。
13. 设备异常报告建立连续记录。
14. 异常核实后创建指派维修工单。
15. 维修人员处理并提交结果，不自行恢复资源。
16. 独立维修验收后恢复可用状态。
17. 系统管理员配置与只读审计权限。
18. 主任报表与审计只读查看。
19. 390像素移动端无页面横向溢出。

页面数据均为模拟示例。预约使用真实当前时间之后的开放时段；未更改电脑时钟。此次页面验收发生在夜间，未声称通过界面完成当时不允许开始的现场设备借还或场地交接。这些现场分支由第4节确定条件的自动化业务测试覆盖，教师白天可按指南准备当前开放时段记录后演示。

曾有验收脚本因既有教师待审核申请而选中个人冲突时段，系统正确拒绝；随后改选无冲突时段验证成功。日期时间控件及浏览器输出格式的自动化填值、解析问题修正后重新确认实际记录与页面路由，没有把脚本失败认定为系统业务通过。

桌面报表及390像素宽移动端截图经目视复核。移动端页面宽度等于视口宽度，无页面横向溢出。报表在新安装且尚无可统计开放历史时显示“不适用”，没有伪造利用率成果。

## 7. 备份与恢复验证

在继承`PGUSER=unrelated`的独立子进程实际执行`python tools/backup_restore.py --restore-test`，结果`verified=true`。本次包含1份完全模拟的PNG证据；数据库恢复到新库，逐表行数一致，有效会话为零，附件文件的SHA-256与记录一致。

本次比对38张公共表，备份、恢复及核对总用时1.883秒。此时间不是单独的恢复时间指标，也不等于已证明任何规模数据都能达到RTO。恢复库未覆盖原演示库，备份包不进入公开提交。后台定时任务只有在启动器及本机运行时才会执行，关机期间不保证按时备份。

## 9. 联验发现与关闭

|发现|处理与复核|
|---|---|
|中文Windows用户的TEMP可能仍含中文，原单一路径选择不足|加入经过目标核验的ASCII短路径及可写备用目录；Windows回归覆盖禁用短路径和错误目录联接目标。|
|英文Windows输出编码可能无法打印中文|启动及停止入口显式采用UTF-8；独立cp1252子进程和实际冷启动复验通过。|
|数据库日志和备份临时文件的Unicode路径兼容性|数据库相关外部工具路径统一使用经核验ASCII别名；本地恢复与远程Windows实际安装、恢复记录通过。|
|机器预置PG变量可能覆盖项目私有数据库配置|私有配置优先，外部数据库需明确启用；11项回归及污染PGUSER情况下的真实恢复通过。|

上述问题按发现、修复、复验记录，没有将联验前的失败隐藏为从未发生。日历并发候选经实际探针排除，没有为未成立的问题增加产品修复。
