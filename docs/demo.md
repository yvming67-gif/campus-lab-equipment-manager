# 课程演示

先 `scripts/setup.ps1`、`scripts/start.ps1`，打开 http://127.0.0.1:8000，从本地 `.local/demo-accounts.json` 获取账号密码。模拟身份不属于真实学校用户。浏览器不同无痕窗口用于不同角色，不要在同一会话频繁覆盖角色后混淆当前账号。

## 正常业务

1. 用 `demo_student1` 登录，查看角色首页 → 实验室 → 设备目录。选择正常、在库的普通设备（如 DEMO-EQ-001；已有案例可查时段后选择其他设备）。
2. 在设备详情查询一个未来对齐半小时的时段。进入提交预约，开始时间取下一个半小时，结束晚一小时，填写用途。查看待审核详情。
3. 用 `demo_labadmin` 登录 → 审核工作台，找到申请 → 审核，填写原因并通过。学生刷新可见通过及通知。教师使用同一审批流程。
4. **真实人工演示须等到开始时间**，并在30分钟领取窗口内办理。管理员从预约详情进入借出，核对实际到场账号、设备标签、配件清单、正常外观及功能并填写检查记录。
5. 进入借用记录 → 办理归还，选择正常并填写配件/功能接收结果。学生查看已完成、实际归还时间；逾期按实际接收时间保存。

不想等待下个半小时，可演示种子中的已借出案例归还；完整预约至领用可用 `manage.py test core.tests.test_browser.BrowserAcceptance.test_flow_1_query_reserve_approve_issue_normal_return` 在隔离库里通过测试时钟运行真实页面。不能把测试时钟用作日常页面跳过规则。

## 竞争预约

1. `demo_student1` 和 `demo_student2` 分别在独立窗口，对同一正常普通设备、同一未来时段提交申请。确保两人的个人时间/数量无冲突。
2. 两个管理员账号在各自窗口打开这两条申请的审核表单，均选择通过并填写原因。
3. 同时确认，最多一条通过，另一条提示已占用。待审核从未占设备时段；审批再次检查和 PostgreSQL 事务锁阻止重复批准。手动先后点击只能展示冲突结果，不能替代并发实测。
4. 可重复真实并发验收：`manage.py test core.tests.test_concurrency.ConcurrencyTests.test_actual_parallel_approval_one_winner`，或 `manage.py test core.tests.test_browser.BrowserAcceptance.test_flow_3_two_applicants_simultaneous_ui_approval` 使用两个 Chromium 会话同时提交。

## 异常归还与维修闭环

1. 在正常流程完成借出后，管理员选择损坏/缺件/运行异常归还。检查归还事实、实际时间已保存，设备为在库+异常隔离。未来受影响预约自动取消并通知。
2. 异常记录中查看已确认异常，创建维修工单，指派 `demo_repair1` 并说明要求。
3. 维修人员登录 → 本人工单 → 保存进度或提交维修结果。提交后为待验收；维修人员页面没有验收按钮，直接构造请求同样拒绝。
4. 管理员查看待验收工单 → 验收通过。无其他异常、开放工单、停用报废或未归还借出才恢复正常。选择验收不通过则退回处理中。
5. 查看原借用仍为已完成、原归还仍存在。可选演示另一个未解决异常或开放工单阻止恢复。

种子包含损坏、缺件和待验收案例，可从维修工作台直接开始。用户异常说明：由借用过该设备的学生从设备详情提交，形成待确认并临时隔离；管理员核验后确认或解决，开放工单不能跳过验收直接恢复。

## 权限、消息与运维展示

- `demo_sysadmin` 展示用户角色、管理实验室授权、培训资格、业务参数与只读审计；该角色不能审核借还。
- 为 `demo_student2` 预约机器人设备展示缺资格拒绝；教师也不会自动绕过限制。
- `demo_student3` 的逾期案例展示预约限制。设备逾期借出阻塞所有未来占用判断。
- 停止常驻 worker 后，`worker --once --mode fail` 演示失败不回滚。到1/5/15分钟重试时刻用 `--mode success` 演示恢复，或用 `--once --at <带时区时间>` 在专门模拟数据中推进。不要把未来任务时间作用于非演示数据库。
- 执行 `scripts/backup.py create`、`scripts/backup.py verify`，展示全表数据摘要一致；恢复验证只使用新库。
- `manage.py reset_demo` 收尾纯模拟活动案例，保留全部历史；`manage.py seed_demo --refresh-cases` 为仍可用模拟设备追加新时间案例。不删除、覆盖或重置非模拟数据。
