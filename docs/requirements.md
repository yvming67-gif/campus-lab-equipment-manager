# 需求基线

来源：用户本次完整提示词。指定《校园实验室设备预约与借用管理系统分析报告》终稿 PDF 在项目及相邻桌面课程资料中未找到。发现的《系统分析与设计-精简2026-9.pdf》为课程教材，未作为终稿使用。**报告原编号、调研结论及原追踪关系尚未核对**；下列 FR/SPEC/BR/AC 是本项目开发基线的自编号，不宣称来自报告。

目标组织是模拟的某高校实验教学中心；所有数据是演示数据。对象为带唯一标签的单台或整套设备。实验室只提供归属、位置、开放信息。本期不实现整间实验室预约、公网部署、付款押金、采购、财务赔偿、物联网或真实学校平台。

## 角色与权限

|角色|允许|数据范围|
|---|---|---|
|学生、教师|查询实验室/设备，预约与取消，查询借用，提交相关异常|预约/借用仅本人；异常仅本人提交；异常说明设备须本人借用过|
|实验室管理员|审核、借出、归还、异常核验、工单创建/指派/验收、设备维护、统计、业务审计|仅被授权实验室|
|维修人员|更新进度、提交结果|仅本人指派工单；相关异常只读；不能验收或恢复设备|
|系统管理员|管理用户角色授权、实验室、培训与参数、只读审计|不自动获得审核借还权限|

模拟统一认证适配器使用 Django 密码哈希及会话，替换点为 `core.identity.MockCampusBackend`。权限与查询范围在服务器校验，前端隐藏按钮只是界面呈现。

## 课程业务假设（待真实制度确认）

默认最多提前14天、30分钟粒度、最长8小时、未来待审核+已通过最多3条、领取宽限30分钟、全人工审批；可由系统管理员在基础数据页面配置。实验室模拟全天开放，未实现按真实教学日历限制开放时段。时间由服务器判定，数据库使用 UTC、页面显示 Asia/Shanghai。

领取窗口 `[预约开始, min(预约开始+宽限,预约结束))`，不允许提前领用。到宽限边界即不再允许借出。任何服务状态非正常或有开放工单均阻塞新申请、批准和借出。高价值/危险设备须有安全培训代码；资格有效期至少覆盖预约结束，教师同样检查。用户有逾期借用不得新预约或获批。

待审核不占设备时段，竞争申请允许同时存在；待审核占个人时间和未来数量。已通过与未结束借用占用设备。个人冲突检查待审核、已通过及未结束借用；冲突为 `new.start < old.end && new.end > old.start`，首尾相接允许。未逾期借出按实际借出至预计归还判断；逾期未归还设备的未来释放时间未知，阻塞所有未来时段，归还后重新判断。

只能取消本人未开始的待审核/通过预约。待审核到开始未批失效，通过到领取宽限未领失效。维护/异常取消受影响的未开始申请并保存原因及通知；借出事实保留。异常归还原子记录接收、异常、隔离；维修不会撤销归还事实。用户相关异常先待确认并临时隔离；管理员可核验解决、继续隔离、创建工单。多工单/多异常全部解决、无停用报废/未归还借出，才可恢复正常。

所有关键变更具备操作者、原因、追踪标识及同事务审计。请求幂等范围为单个用户+请求 UUID，重复同内容返回原结果，内容不同拒绝，失败事务不保留收据。通知站内先落库，模拟外部服务事务外发送，首次失败后1/5/15分钟重试。临近归还定义为一小时内，逾期通知每个借用发一次。

## 功能与质量编号

FR-01 设备时段查询；FR-02 申请与额度；FR-03 人工审批；FR-04 取消与失效；FR-05 身份/实物核验借出；FR-06 归还检查；FR-07 异常确认隔离；FR-08 工单与验收；FR-09 模拟认证；FR-10 实验室；FR-11 记录筛选分页；FR-12 相关异常说明；FR-13 工单指派；FR-14 设备维护；FR-15 用户角色；FR-16 基础数据；FR-17 审计；FR-18 通知与重试；FR-19 利用率。

UC-01—UC-19 保持用户指定编号，名称和位置见追踪矩阵。SPEC-01—SPEC-19 为对应实现规格；BR-01—BR-19 为对应规则集合；AC-01—AC-19 为对应验收场景，不虚构任何报告编号。

质量目标：明确课程负载下查询 P95≤3秒，普通提交 P95≤5秒，成功后5秒内可重新查询；密码哈希、会话、CSRF、后端权限、不可篡改审计；真实 PostgreSQL 独立连接并发测试和事务故障注入；真实浏览器三条流程；备份恢复实测。RPO24h/RTO4h 是需调度、异机副本、凭据及环境准备支撑的初步目标。实际结果与未验证内容见验收文档。
