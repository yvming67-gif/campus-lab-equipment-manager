# 数据模型与图形源文件

本目录描述实际应用领域模型：**36个实体、289个字段、61条物理外键**。实体、字段与约束以`schema.json`及迁移为准，图形不另建一套与代码不一致的模型。

## 先选择阅读方式

- [完整ERD总图（矢量PDF）](ERD/完整ERD总图.pdf)：A0横向大幅图，适合缩放查看全局和字段；不建议缩印到单张A4。
- [分域ERD图册（矢量PDF）](ERD/分域ERD图册.pdf)：六页A4纵向，逐域展开全部字段，适合普通打印。
- [离线交互图谱](ERD/交互图谱.html)：下载整个仓库后在浏览器打开，支持缩放、实体或字段搜索及共享引用图层切换；不依赖网络服务。
- [完整关系索引](ERD/关系索引.csv)：R01-R61与所有真实外键、基数、可空性和删除策略对应。
- [完整可编辑总图](图形源文件/ERD-00-完整实体关系总图.drawio)：用diagrams.net打开；字段、卡片和关系均可编辑。

## 读图约定

A身份与权限、B资源与开放、C预约与规则、D现场使用、E异常与维修、F审计与通知构成六个数据域。实体代码用于跨域定位。每张卡片保留模型名、中文职责、实际表名及全部列；金色钥匙为PK，蓝色目标为FK，`?`为可空，`UQ`为单列唯一。圆圈表示零、竖线表示一、乌鸦脚表示多。

总图实线展示域内和主要业务外键。高频人员、管理责任等跨域共享引用在字段行标明关系编号、目标表和实体代码；共享引用连线默认隐藏，避免长线遮挡。draw.io“共享引用”图层或离线图谱的开关可显示全部61条连接。图中字段目标、关系索引和完整源文件始终保留这些关系。

`AuditEvent.entity_type + entity_id`是逻辑对象引用，没有伪造为物理外键。`User`继承的框架兼容列保留在完整字段中，不代表演示系统存储学校密码；领域外的会话、框架权限组和迁移表不混入本图。`MockReceipt`属于独立模拟消息适配器。

## 文件与编辑

- `schema.json`：由Django实际模型导出的全部字段、索引、约束与外键。
- `campus_lab.dbml`：可导入DBML工具；组合、条件唯一、区间排斥及跨表规则以迁移与数据设计说明为准。
- `campus_lab.mmd`：完整Mermaid ERD，可用于关系复核。
- `图形源文件/ERD-00-*`：大幅完整总图的draw.io与SVG。
- `图形源文件/图D-1-*`：数据域导航，属于目录，不冒充物理ERD。
- `图形源文件/图D-2-*`至`图D-7-*`：六个域的完整字段draw.io与SVG。
- `图形源文件/图3-*`、`图4-*`：业务建模与系统用例的可编辑UML图。
- `ERD/manifest.json`：模型摘要、完整字段清单、关系端点及正交路线，用于一致性验证。

## 重新生成

运行应用无需安装绘图软件或以下可选依赖。只有修改数据模型或图形时需要：

```powershell
python tools/export_model.py
python -m pip install -r requirements-erd.txt
python tools/render_erd.py
python tools/validate_registry.py
```

矢量PDF嵌入中文字体。生成器默认读取Windows的微软雅黑、Consolas和Arial；其他系统可通过`CAMPUS_CJK_FONT`指定可嵌入的中文TTF/TTC。字体仅用于本机渲染，不随仓库分发。可选安装PyMuPDF后使用`python tools/render_erd.py --preview`更新PNG预览，常规PDF与SVG生成不需要PyMuPDF。

模型只表达结构及可执行约束，不能把外键本身当成角色授权、子类型完整性或跨表业务规则的证明；这些规则由统一服务、事务及数据约束共同执行。
