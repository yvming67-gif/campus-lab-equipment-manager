面向高校实验教学中心的设备借用与场地预约系统。学生和教师可查询资源、提交申请并查看进度。实验室管理员、维修人员及其他岗位在网页处理各自的业务。网页和原生微信小程序共用 Django 后端与 PostgreSQL 数据库。在线环境使用模拟身份、资源和业务数据。

## 快速开始

### 在线网页

1. 打开[校园实验资源中心](https://campus-lab-equipment-manager.onrender.com/login/)，点击「选择演示账号」。
2. 选择 `student` 或 `student2`（学生），或 `teacher`（教师）。这三个公开账号使用密码 **`Demo@2026`**。
3. 登录后从资源目录查找「数字示波器」，选择可用时段并提交预约。普通设备通过检查后自动确认。仅教师可申请整间实验室，申请提交后进入待审核。

公开账号的预约、消息和配额由使用同一账号的人共享。持独立密码的岗位和专用师生账号也从同一网页登录，账号及职责见[角色与能力](#角色与能力)。免费服务休眠后的首次打开可能等待约一分钟。[项目入口与访问说明](docs/项目入口.md) · [按角色操作指南](docs/演示操作说明.md)

## 角色与能力

| 角色 | 网页账号 | 主要操作 |
| --- | --- | --- |
| 学生 | `student`、`student2`、`student_lab` | 查询与预约设备、查看进度、取消预约、报告异常 |
| 教师 | `teacher`、`teacher_lab` | 预约设备及整间实验室、跟进课程资源安排 |
| 实验室管理员 | `admin` | 审核所负责实验室的申请、办理设备借还与场地交接、核实异常、指派维修及验收 |
| 维修人员 | `tech` | 查看本人维修任务、记录处理进展并提交维修结果 |
| 系统管理员 | `sysadmin` | 维护角色授权、基础数据、预约参数及默认开放日历 |
| 实验教学中心主任 | `director` | 查看中心利用率报表和只读审计记录 |

`student_lab`、`teacher_lab` 及四个管理与协作岗位使用各自的密码，由部署方私下提供。小程序提供师生查询与预约。管理操作在网页完成。

## 资源结构与安全信息

网页和小程序的资源详情读取对应的场地或设备档案。安全内容通过带来源、版本和复核期限的记录发布，可设为管理单元通用信息或具体资源专属信息。详情仅展示已发布的安全信息。

```mermaid
flowchart LR
  A[演示管理单元] --> B[独立场地资源 A]
  A --> C[独立场地资源 B]
  A --> D[设备资源]
  B -. 固定设备关联（如适用） .-> D
  A --> E[管理单元通用安全信息]
  B --> F[场地专属安全信息]
  D --> G[设备专属安全信息]
  E --> H[授权复核与发布]
  F --> H
  G --> H
  H --> I[网页 / 微信小程序按明确适用范围读取]
```

资源专属信息只适用于指定场地或设备；固定设备不会自动继承所在场地的专属版本。管理单元通用信息是否适用于某项资源，仍以正式批准的适用范围为准。

资源名称、地点、容量与设施均为课程模拟数据；真实实拍图需经过资源对应、授权和隐私核验后才可加入。玻璃效果使用 CSS 和 WXSS 实现。详见[图片来源与授权](docs/图片来源.md)、[案例研究与设计决定](docs/案例研究与设计决定.md)和[资源目录与安全信息](docs/场地目录与安全信息.md)。

## 运行方式

### Windows本机运行

1. 安装[Python 3.13 x64](https://www.python.org/downloads/windows/)，勾选“Add python.exe to PATH”。
2. 点击本仓库 **Code → Download ZIP**，完整解压。
3. 双击 **启动演示.cmd**。首次需联网、约2GB可用磁盘，并下载约364MB的PostgreSQL组件；无需预装Git、Node.js或数据库服务。
4. 使用启动窗口显示的地址，默认 `http://127.0.0.1:8000`；端口占用会自动选择空闲端口。

本机默认的七个模拟账号统一使用密码 **`Demo@2026`**，包括 `admin`、`tech`、`sysadmin` 和 `director`。[本机账号及职责](docs/项目入口.md#windows本机账号)

保留启动窗口；按 `Ctrl+C` 停止网页与后台，双击 **停止数据库.cmd** 停止本项目数据库。再次启动保留数据；私有配置在不提交的 `.local`，依赖在 `.venv`。[运行指南](docs/运行指南.md) · [已有PostgreSQL及开发检查](docs/开发与验证.md)

## 业务约定

- 学生和教师可申请设备，仅教师可申请整间场地；可移动设备独立预约，固定设备遵守关联场地限制。
- 普通设备规则检查后自动确认；受限设备与场地人工审批。待审核不占时段，但计入个人未来配额，批准前重新检查。
- 默认未来14天、30分钟粒度、同日最长8小时；按开放日历执行。每类未来预约最多3项，同时最多使用3台或套设备。
- 候选时段只是查询快照。资源、资格、冲突与配额由服务端在提交和批准时重新核验。
- 实际交接与计划分开记录；异常分级核实，维修执行与验收分离，恢复前检查全部限制。
- 状态历史只追加。站内通知与业务同事务保存，外部消息失败不得撤销已保存业务；未知结果重试保留原请求标识。

这些属于课程基线，不能据此推定某所学校已有同样制度。[需求与规约](docs/逻辑整改/README.md) · [接口契约](docs/接口与通道.md)

## 技术与维护

Python 3.13 / Django 5.2 / PostgreSQL 17，网页采用Django模板，小程序采用原生JS/WXML/WXSS。常规网页运行无需前端构建。

```text
core/          领域服务、权限、接口、任务及测试
templates/     网页模板
static/        样式、交互与经许可后方可加入的项目资源照片目录
miniprogram/   师生原生微信端
docs/          正式分析、模型说明、运行与验证文档
models/        ERD及可编辑UML源文件
tools/         启动、校验、备份及恢复工具
```
